# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-11-11
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

Bric-à-Jeux (PRD v0.1.0) is a collection of three mini-games plus a meta-game, with these technical needs:

- **Rendering**: pixel-art sprites drawn in code (8×8 to 16×16 palette grids). Pluie de Blocs draws a 10×16
  board (160 cells) with a falling piece at the display refresh rate; Bulles en Folie draws up to 108 grid bubbles
  plus a flying bubble, an aim guide with bounces, pop and drop animations; Potager Fou animates swaps, falls and
  cascades on 56 cells. Each sprite is made of dozens of pixels, so a Views-per-pixel approach would mean thousands
  of nodes: this is the "many sprites, custom drawing" case of `game-patterns.md`, which calls for a Skia canvas
  driven by Reanimated shared values. The meta-game screens (Home, Worlds, Profile, Settings...) are ordinary
  React Native Views.
- **Input**: single-finger drag, tap, swipe, hold-and-release (`react-native-gesture-handler`).
- **Audio and haptics**: sound effects without music (`expo-audio` + `expo-asset`), light haptics (`expo-haptics`).
- **Font**: a free pixel font (OFL) loaded with `expo-font`.
- **Storage**: one JSON save in `@react-native-async-storage/async-storage`.
- **Deep link** for deterministic Maestro flows (`miniworlds://seed/<n>`): `expo-linking` + the intent filter
  from `app.config.js`.
- **Firebase**: Analytics + Crashlytics, opt-in, through `@react-native-firebase/app` and `/crashlytics` config
  plugins; AD_ID permission removed.
- **Localisation**: fr + en, launcher name per language (strings resources generated at prebuild by the factory
  overlay).
- **Build**: local only, on Windows, signed arm64 APK sideloaded on the phone; no EAS, no cloud.
- No sensor, no camera, no custom native code, no backend. iOS is out of scope but was mentioned as a possible
  future port.

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes | yes | Skia + Reanimated 4 + worklets proven on SDK 57 by ganja-farmer and nightstalker; gesture-handler, expo-audio, expo-haptics, expo-font, expo-linking, AsyncStorage are standard; RNFB has config plugins |
| Need to hand-edit native Android code continuously | high | no | no | nothing native beyond what plugins already cover (signing, launcher strings, AD_ID removal) |
| Custom native module (Kotlin/C++) needed | medium | no | no | all game logic is pure TypeScript; rendering is Skia |
| Upgrade effort over time | medium | low (SDK bump + `expo install --fix`) | medium (Upgrade Helper, native diffs) | a long-lived app with new mini-games added over months benefits most |
| Build simplicity on this machine (local Gradle) | medium | proven (9 Expo apps built here) | proven (1 app) | `build-apk.mjs` handles both |
| Firebase setup effort | low | config plugins | manual Gradle edits | |
| Possible iOS port later | low | cheaper | more work | mentioned in the original brief, not a goal |

## Decision

**Expo SDK 57 with Continuous Native Generation**, game boards rendered in a **Skia canvas**
(`@shopify/react-native-skia`, pixel sprites pre-rasterised once into Skia images and drawn with nearest-neighbour
sampling), animation state in **Reanimated** shared values, input with **Gesture Handler**, meta-game screens in
plain React Native Views.

1. Every library the PRD needs works with Expo prebuild, and the Skia + Reanimated + worklets combination is
   already proven on SDK 57 by two apps of this factory.
2. Nothing needs hand-written native code: the whole game (three engines and the core meta engine) is pure
   TypeScript, tested by Jest and deterministic under a seed.
3. The app is meant to grow for months (new mini-games as modules): Expo's upgrade path and config plugins keep
   that cheap, and a later iOS port stays possible.

## Consequences

- `android/` is generated by `npx expo prebuild` and git-ignored; native changes go through config plugins and
  `app.config.js`.
- Skia and Reanimated add about 10 MB of native libraries: the APK size target is < 55 MB instead of < 40 MB
  (PRD non-functional requirements already allow it).
- Pixel sprites: a `Sprite` is a palette grid in TypeScript; a renderer module rasterises each sprite once into a
  Skia image (one per sprite and theme) and draws it scaled with `FilterMode.Nearest`, so pixels stay crisp.
  Unit tests check the grids (AC-44); the rendering is proven by Maestro screenshots.
- Real-time games run their `tick` on a `useFrameCallback`; the engine stays outside React and the canvas reads
  shared values, so React re-renders only on game events (score, end).
- Known pitfalls (ganja-farmer, nightstalker): install Skia together with Reanimated and worklets; clear the Metro
  cache if a build bundles Skia without worklets; `expo-audio` needs `expo-asset` and no `recordAudioAndroid`.

## Alternatives considered

- **Bare React Native**: no criterion of `stack-decision.md` requires it; it would only add manual Firebase and
  signing setup and a heavier upgrade path.
- **Views + Reanimated instead of Skia**: fine for the meta-game screens (kept there) but the pixel sprites would
  need thousands of Views on the game boards; Reanimated's own guidance points to a canvas beyond ~100 animated
  nodes on low-end Android.
- **expo-gl + three**: 3D is not needed; Skia is simpler for 2D sprites and already in use in the factory.
- **Pre-rendered PNG sprites**: rejected at discovery (sprites are code, no binary assets to maintain).
